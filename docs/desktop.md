# Desktop workspace

Goal 0011 puts the headless study engine in a MyGo desktop window. The window is a second surface over
the same Go core: it never reimplements a scoring, selection, consent, budget or assessment rule.

Contract: [`goals/archive/0011-desktop-study-workspace.md`](goals/archive/0011-desktop-study-workspace.md). Plan:
[`plans/2026-11-14-1600-0011-desktop-study-workspace.md`](plans/2026-11-14-1600-0011-desktop-study-workspace.md).
Design direction ("C · Stage", chosen by the owner): [`../design/prototypes/c-stage.html`](../design/prototypes/c-stage.html)
and its brief [`../design/prototypes/BRIEF.md`](../design/prototypes/BRIEF.md).

## Build and run

```bash
bun install
bun run desktop:build        # bundles desktop/web, builds build/desktop/passquest-desktop[.exe]
build/desktop/passquest-desktop
```

`go build ./cmd/passquest-desktop` alone compiles without the bundle (the bundle is generated, not committed);
such a binary opens a "frontend not built" page instead of a blank window. With arguments the desktop binary
behaves exactly like `passquest` (`passquest-desktop report --json` …), which is how the durable host calls
`agent record-step` back on it.

Prerequisites: Windows 10/11 with the WebView2 runtime (bundled with Windows 11); macOS 12+; Linux with GTK 3
and WebKitGTK 4.1. Node ≥ 22 is needed only for the coach, Anki push, find and the study brief — practice,
feedback, assessment and notes work without it.

## Layout

| Path | Role |
|---|---|
| `cmd/passquest-desktop` | entry point: CLI arguments → `cli.Run`, none → the window |
| `internal/studio` | exported DTOs of the bound API (pure data, JSON snake_case) |
| `internal/cli/workspace*.go` | the `Workspace` service: the CLI's own orchestration exposed as typed calls |
| `internal/desktop` | MyGo app: bound `Study` service, data directory, OS credential store, lifecycle, smoke hook |
| `internal/desktop/web` | `go:embed` root: committed `index.html`, generated `dist/` |
| `desktop/web` | TypeScript + CSS source; `src/api/mygo.ts` is generated by MyGo from the bound service |

`cmd/passquest` keeps linking no HTTP client; MyGo links `net/http` only into the desktop binary, and no
first-party package imports a network package directly (the local-only gate checks both).

## Truth and state

- **Data.** The window uses its per-user data directory (`passquest.sqlite` inside it); `PASSQUEST_DB`
  overrides (Q-0011-04). The CLI default is unchanged.
- **Presentations.** Displaying an item records a presentation, as `show` does (Q-0011-08); it is the start of
  the attempt's elapsed time and the resume point after an interruption. Answering twice with the same token
  returns the stored feedback and writes no second attempt.
- **Condition before answering.** The item carries the condition and whether it can count, computed by the
  same classification the report uses. Opening a hint (only where an authored walkthrough exists, Q-0011-05)
  records an exposure and turns the attempt assisted.
- **Assessment.** The window uses the CLI's step functions; the clocks on screen are derived from the stored
  deadlines, and the server decides timeouts. While a run is active, Today spends nothing.
- **Exam date and daily minutes** are optional, display-only settings (Q-0011-06). The pass threshold is always
  shown as unknown.

## Credentials

A key entered in Settings goes to the OS credential store (Windows Credential Manager, macOS Keychain, Secret
Service on Linux) under the app identifier; an environment variable still wins (Q-0011-03). The window and the
DTOs only ever see `present`/`missing`. Where no store is available, Settings says so and environment variables
remain the only path. Nothing credential-bearing is written to SQLite, logs or exports.

## Lifecycle

The process opens no TCP listener (single-instance locking uses a local socket file). Node hosts are spawned
per call as the CLI spawns them and are reaped on quit: a job object on Windows, a process group on macOS and
Linux. Quit waits a bounded time for in-flight calls.

## Smoke hook

For the `desktop-smoke` gate the app honours `PASSQUEST_DESKTOP_HIDDEN`, `PASSQUEST_DESKTOP_DATA`,
`PASSQUEST_DESKTOP_SECRET_SERVICE`, `PASSQUEST_DESKTOP_SCRIPT` (a file whose content runs in the page as an
async function body after load) and `PASSQUEST_DESKTOP_RESULT` (where the JSON result is written before quit).
It is a file-based hook for a local process that can already launch the app with its own environment; it adds
no network surface.
