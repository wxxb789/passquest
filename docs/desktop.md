# Desktop workspace

Goal 0011 puts the headless study engine in a MyGo desktop window. The window is a second surface over
the same Go core: it never reimplements a scoring, selection, consent, budget or assessment rule.

Contract: [`goals/archive/0011-desktop-study-workspace.md`](goals/archive/0011-desktop-study-workspace.md). Plan:

## Build and run

```bash
bun install
bun run desktop:build        # bundles desktop/web, builds build/desktop/passquest-desktop[.exe]
build/desktop/passquest-desktop
```

`go build ./cmd/passquest-desktop` alone compiles without the bundle (the bundle is generated, not committed);
such a binary opens a "frontend not built" page instead of a blank window. With arguments the desktop binary
behaves exactly like `passquest` (`passquest-desktop report --json` …), which is how the durable host calls
`agent record-step` back on it.

Prerequisites: Windows 10/11 with the WebView2 runtime (bundled with Windows 11); macOS 13+; Linux with GTK 3
and WebKitGTK 4.1. Node ≥ 22 is needed only for the coach, Anki push, find and the study brief — practice,
feedback, assessment and notes work without it.

## Layout

| Path | Role |
|---|---|
| `cmd/passquest-desktop` | entry point: CLI arguments → `cli.Run`, none → the window |
| `internal/studio` | exported DTOs of the bound API (pure data, JSON snake_case) |
| `internal/workspace/*.go` | the `Workspace` service: the `internal/study` modules exposed to the window as typed calls |
| `internal/desktop` | MyGo app: bound `Study` service, data directory, OS credential store, lifecycle, smoke hook |
| `internal/update` | the on-demand release check: the window's one network request, and the only first-party package that imports `net/http` |
| `internal/desktop/web` | `go:embed` root: committed `index.html`, generated `dist/` |
| `desktop/web` | TypeScript + CSS source; `src/api/mygo.ts` is generated by MyGo from the bound service |

`cmd/passquest` keeps linking no HTTP client; MyGo links `net/http` only into the desktop binary, and
`internal/update` is the one first-party package that imports it directly — the on-demand update
check's single request ([Core Design](core-design.md) §6). Only `internal/desktop` and
`cmd/passquest-desktop` may import it, every other first-party package still imports no network
package, and the CLI's dependency tree must not contain it (the local-only gate's rules 1–4).

## Truth and state

- **Data.** The window uses its per-user data directory (`passquest.sqlite` inside it); `PASSQUEST_DB`
  overrides (Q-0011-04). The CLI default is unchanged.
- **Presentations.** Displaying an item records a presentation, as `show` does (Q-0011-08); it is the start of
  the attempt's elapsed time and the resume point after an interruption. Answering twice with the same token
  returns the stored feedback and writes no second attempt.
- **Condition before answering.** The item carries the condition and whether it can count, computed by the
  same classification the report uses. Opening a hint (only where an authored walkthrough exists, Q-0011-05)
  records an exposure and turns the attempt assisted.
- **Assessment.** The window calls the same `internal/study/assessment` step functions as the CLI; the clocks on
  screen are derived from the stored deadlines, and the server decides timeouts. While a run is active, Today
  spends nothing.
- **Exam date and daily minutes** are optional, display-only settings (Q-0011-06). The pass threshold is always
  shown as unknown.

## Anki card, AI refinement and coach history (goal 0012)

- **Card preview from the backend.** `PreviewNote(draftID, fields)` returns the card as complete documents:
  `question` and `answer`, each with `light` and `night` (`NoteCardSide`), built by `note.CardDocument` from
  the real templates and stylesheet with the body classes Anki uses (`card card1`, plus `nightMode night_mode`
  at night). The window composes no card markup: each shown side is the document placed byte for byte in an
  `<iframe sandbox="allow-same-origin" scrolling="no" srcdoc>`. No script runs in the frame; the window reads
  the frame document's height and sizes the frame to it, so the card is never clipped and never scrolls.
  Side (both/front/back), light/night and desktop/phone width are window toggles over the same documents.
  `fields_sha256` identifies the field payload a push would send (`html_sha256` is the same value under its
  earlier name); `css_sha256` is the sha256 of the model stylesheet `passquest note model --json` prints, and
  `model_version` its design version. `html`/`css` remain for older readers.
- **Push outcome.** `PushNotes` also reports `model_updated` (an earlier Pass Quest card design in Anki was
  replaced in place) and `model_customized` (the note type was changed in Anki and left as it is; the notes
  were still pushed). The window shows either one after a push.
- **Refine with AI.** `RefineNotePreview(draftID)` shows, before anything is sent, the provider and model,
  local or external, verification and credential state, the consent covering the provider, the exact
  messages with their sha256 and size, and the budget slot; while consent withholds the source text it
  carries no messages and no hash. `RefineNote(draftID)` makes one call through the same path as
  `note propose --refine` and returns an advisory suggestion (`NoteRefinement`) or a typed error. The window
  renders the suggestion as text beside the fields; "Use suggestion" only fills the editor, and accepting
  stays the learner's action. The editor's fields stay the draft's own (the deterministic text, or what was
  last accepted); a suggestion is kept beside them, and `OpenNoteDraft` returns it as `suggestion` after a
  relaunch instead of putting it into the fields. An emptied field falls back to the draft's own value, never
  to the suggestion. On accept, a field equal to the draft's own value keeps its origin, one equal to the
  suggestion is recorded as `refined`, and anything else as `edited`. Retry after a failure only shows the
  preview again. While a send waits, Accept and Skip are disabled with the reason beside them; closing the
  panel hides the request without dropping it, and reopening shows it waiting and then its reply, never a
  fresh preview, so one draft never has two refinements in flight from the window. A reply that comes
  back after the draft was accepted or skipped elsewhere changes nothing: `RefineNote` returns
  `draft_changed`, the call stays recorded and the draft keeps what was accepted. The backend also refuses a second
  `RefineNote` for a draft whose refinement is still waiting (`refine_in_progress`, nothing sent), so a
  reload or another route cannot start one either.
- **Coach history.** `CoachHistory(attemptID)` lists the attempt's recorded coach calls, oldest first, with
  mode, provider, model, time and state; an advisory call carries its reply text, a failed one its typed
  failure. It carries no credential and no request body. The coach sheet shows it as text in its history view.

## Credentials

A key entered in Settings goes to the OS credential store (Windows Credential Manager, macOS Keychain, Secret
Service on Linux) under the app identifier; an environment variable still wins (Q-0011-03). The window and the
DTOs only ever see `present`/`missing`. Where no store is available, Settings says so and environment variables
remain the only path. Nothing credential-bearing is written to SQLite, logs or exports.

## Lifecycle

The process opens no TCP listener (single-instance locking uses a local socket file). Node hosts are spawned
per call as the CLI spawns them and are reaped on quit: a job object on Windows, a process group on macOS and
Linux. Quit waits a bounded time for in-flight calls.

## Smoke hook

For the `desktop-smoke` gate the app honours `PASSQUEST_DESKTOP_HIDDEN`, `PASSQUEST_DESKTOP_DATA`,
`PASSQUEST_DESKTOP_SECRET_SERVICE`, `PASSQUEST_DESKTOP_SCRIPT` (a file whose content runs in the page as an
async function body after load) and `PASSQUEST_DESKTOP_RESULT` (where the JSON result is written before quit).
The update check adds two more, read only while `PASSQUEST_DESKTOP_SCRIPT` is set:
`PASSQUEST_DESKTOP_UPDATE_URL` and `PASSQUEST_DESKTOP_UPDATE_TIMEOUT_MS`. Only an
`http://127.0.0.1:<port>` URL, and a timeout no longer than a real check's, are honoured, so a scripted
launch can point the check at a stub inside the harness process and a packaged run can still reach only
the constant endpoint (Q-0015-06). The hook is file-based for a local process that can already launch the
app with its own environment; it adds no network surface beyond the loopback endpoint the update
variables may name.
