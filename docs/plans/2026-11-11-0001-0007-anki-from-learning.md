## Goal in one sentence

Turn the high-value signal of a stored attempt or an explicit learner mark into one concise,
inspectable Anki note: deterministic locally, source-linked, consent-gated when the material is an
imported private source, persisted exactly once by content, exported atomically as HTML/TSV, and
pushed to a loopback AnkiConnect endpoint with duplicate/update/queue semantics proven against a stub.

## Public shape

```text
passquest note propose [--attempt ID] [--content CONTENT --question QUESTION] [--mark TEXT]
                       [--refine] [--db PATH] [--json]
passquest note preview [--draft ID] [--db PATH] [--json]
passquest note accept  [--draft ID] [--front TEXT] [--back TEXT] [--tactic TEXT]
                       [--db PATH] [--json]
passquest note skip    [--draft ID] [--db PATH] [--json]
passquest note show    [NOTE] [--db PATH] [--json]
passquest note model   [--json]
passquest note export  [--out PATH] [--db PATH] [--json]
passquest note push    [--endpoint URL] [--timeout-seconds N] [--force] [--db PATH] [--json]
```

- `propose` resolves one target. With no target flag it uses the latest attempt. `--attempt N` names
  an attempt; `--content CONTENT --question QUESTION` names a reviewed question that need not have
  been answered. `--mark` records the learner's explicit high-value signal. `--refine` sends the
  deterministic draft to the configured goal-0005 endpoint once.
- `preview` renders the exact four field values that `accept`, `export` and `push` would write, after
  the current consent decision is applied. It never contacts a provider or Anki.
- `accept` writes the open draft as the current local revision. `skip` closes the draft without a note.
- `show` is read-only: current revision plus every retained revision.
- `model` prints the deck/model name, fields, CSS and card templates plus a rendered sample; it exists
  so acceptance 6 is inspectable without Anki.
- `export` writes `#`-prefixed importer options, a header row, and one tab-separated row per note to a
  temporary file in the destination directory, syncs it, and renames it into place.
- `push` creates the deck and model when missing, then adds or updates notes. An unreachable endpoint
  leaves every pending note queued and exits 0; the next reachable push drains them once.

Exit codes: `0` success (including queued because no endpoint answered) · `2` invalid input, no open
draft, low-value target, missing consent, no configured provider, not-practiceable question ·
`3` provider or Anki failure after an external attempt, including an Anki host that cannot start ·
`1` local storage or export I/O failure.

JSON is `schema_version: 1`, one document per command, failures on stderr with the existing
`{error: {code, message}}` shape.

## Target and draft semantics

Two signals choose a note, never every question seen (Q-0007-05):

| Target | Allowed without a mark | Draft front |
|---|---|---|
| incorrect attempt | yes | the recorded correct option text (the missed wording) |
| skipped attempt | yes | the question's registered tactic title, else the stem |
| correct attempt | **no** — `low_value`, exit 2 | the mark |
| reviewed question, no attempt | only with `--mark` | the mark |

`--mark` is trimmed, length 1–120 code points, tabs/newlines collapsed to spaces, and is the learner's
own text: it is not treated as authoritative content.

The draft is deterministic and key-safe:

- `front` — the mark, else the incorrect attempt's recorded correct option text, else the tactic title
  or question stem for a skipped attempt.
- `back` — two plain paragraphs separated by a blank line: the meaning/explanation and one
  exam-usable example. The meaning is authored question/option reasoning when the learner already
  answered incorrectly, a first-party tactic principle otherwise. The example is the reviewed
  evidence sentence, or the stem when the evidence is unavailable.
- **Never** for an unanswered target (no attempt or skipped): the correct option label, correct option
  text, `question.answer`, the keyed option's option-reasoning, or `question.reasoning`. Those fields
  can name the answer, so the builder does not read them on that branch. A skipped attempt is
  unanswered even though the app has a key.
- `tactic` — `attempt.tactic_id`, else the first registered scoring skill in the recorded skill
  snapshot, else the first registered scoring tag on the current question, else the first registered
  tag. The Anki field carries the authored skill title; JSON carries both id and title.
- `source` — `source_id · p<NNN> · <question_id>` for an imported page, or `sample · <content_id> ·
  <question_id>` for first-party content. No source title is used, so a private title cannot leak.
- `restricted` — true for every imported source, matching the goal-0005 `private_source` rule
  (Q-0007-08). First-party sample and skill content is false.

### Consent

`restricted && !consent_granted` withholds `front`, `back` and the example from preview, draft fields
and any write. The tactic (first-party lesson text) and source identifiers remain visible, so the
learner can see what the note is about. `accept` is refused with `consent_required` naming
`passquest tutor consent SOURCE --reviewer NAME`; `export` and `push` only ever see accepted notes.
Consent is the existing append-only goal-0005 ledger; revoke takes effect on the next preview.

## Note identity and persistence

A note is identified by the question plus the marked wording:

```text
target_key = content_id + "\x1f" + question_id + "\x1f" + lower(trim(mark))
note_id    = "note-" + first 16 hex chars of sha256(target_key)
```

One question without a mark yields one note; two marks on the same question yield two notes. The
derived id makes a repeated accept report the same note even after the draft row is gone.

Schema v10 adds five tables. No table can update `attempts`, a source, a question or an answer key.

| Table | Ownership |
|---|---|
| `note_drafts` | Target inputs (`attempt_id`, content/question/source/page, mark), `restricted`, origin, refinement text. One open draft per target via a partial unique index; a new mark supersedes the previous open draft. Transient, mutable, not learner evidence. |
| `notes` | Current local note: target, revision, plain front/back/tactic/source text, content hash, restricted flag, Anki id and pushed revision. |
| `note_revisions` | Append-only history: one immutable row per accepted revision, unique `(note_id, revision)`. Update/delete rejected by triggers. |
| `note_outbox` | One desired revision per note with `pending`/`drained`/`failed`/`conflict`, attempt count, last error, drained time. A repeated accept at the same content does not enqueue. |
| `anki_push_attempts` | Append-only ledger of every add/update/readd per note (`ok`, `duplicate`, `not_found`, `conflict`, `failed`, `unreachable`), so exactly-once draining and retries are countable. |
| `note_refinements` | Append-only provider refinement record: model, prompt version, request SHA-256/bytes, output, usage, failure code. |

`accept` runs one transaction:

1. Resolve the open draft (latest, or `--draft`), apply `--front/--back/--tactic` overrides.
2. Compute the canonical content hash over plain front/back/tactic/source and the restricted flag.
3. Existing note with the same hash → **unchanged**: return its id and revision; insert no revision and
   enqueue nothing.
4. Existing note with a different hash → insert revision `n+1`, update the current row, upsert the
   outbox at the new revision, retaining every earlier revision.
5. New note → insert note, revision 1, outbox pending revision 1.

`skip` marks the draft skipped; it never deletes an accepted note or a revision.

### Refinement

`propose --refine` requires a configured goal-0005 provider and credential. It reserves one slot in
the shared daily provider budget (`tutor_calls` + in-flight reservations + `note_refinements`), builds
one chat request in Go, calls the existing `agent/tutor-host.mjs` through `tutor.Transport`, and
records the outcome in `note_refinements` in the same transaction that releases the reservation. The
prompt returns strict JSON `{front, back}`, receives no key for an unanswered target and no imported
text without consent (restricted + no consent refuses refinement with `consent_required`). A failure
records the attempt, exits 3, and leaves the deterministic draft open and acceptable. Refined text is
labelled advisory in JSON and human output; the learner accepts it explicitly.

## AnkiConnect adapter

The Go core must not import `net`/`net/http` (the `local-only` gate). As with the tutor, the Node host
`agent/anki-host.mjs` is the only Anki egress: one versioned stdin/stdout document carrying a bounded,
allow-listed action list; it posts each action to the endpoint and returns the raw result and Anki's
error string. The Go side owns all policy and classification, so it is testable without Node.

- Endpoint default `http://127.0.0.1:8765`, overridable with `--endpoint` or
  `PASSQUEST_ANKI_ENDPOINT`; `http`/`https` only, no userinfo, and the host must be loopback
  (`127.0.0.1`, `localhost`, `[::1]`). A remote host is refused with exit 2: a note contains private
  source text and AnkiConnect is a local bridge.
- Actions: `version` (must be ≥ 6), `createDeck`, `modelNames`, `createModel`, `addNote`,
  `updateNoteFields`, plus `notesInfo` for the read-back that Q-0007-06 requires before overwriting.
- `addNote` uses `allowDuplicate: false`. Anki's duplicate error is classified as `already_present`,
  is reported as a normal outcome (exit 0) and does not mark the note failed. Because AnkiConnect
  reports no id for a duplicate, the local note keeps `anki_note_id = 0`; a later edited revision is
  surfaced as a conflict rather than silently adding a second card.
- A revision with an Anki id first calls `notesInfo`. If the fields no longer match the revision last
  pushed, the note is a **conflict**: Anki is left untouched and `push` exits 3 naming the note.
  `--force` is the explicit control that overwrites it. If the note is gone (`note not found`), the
  adapter re-adds it once, records a `readd` attempt and stores the new id; there is no review history
  left to preserve.
- Otherwise `updateNoteFields` updates the recorded id, so no second card is created and Anki's review
  history survives.
- No endpoint answers → every pending note stays queued, `push` reports `queued` and exits 0. A second
  push drains each pending revision exactly once; the outbox is marked drained and the attempt ledger
  shows one write. A transport failure after a request was sent keeps the note pending: retry is safe
  because `addNote` deduplicates and `updateNoteFields` is idempotent.
- The Anki host is optional: `export`, `propose`, `preview`, `accept`, `skip`, `show` and `model` work
  with no Node and no Anki. `push` reports `anki_unavailable` (exit 3) with the pending notes intact.

Batches keep process count low: one call for `version`/`createDeck`/`modelNames`, one conditional
`createModel`, one `notesInfo` batch, then one add/update batch. Every action result is bounded and
the host never logs field text.

## Note model and template

Constants owned by `internal/note`:

- Deck `Pass Quest`, model `PassQuest Note`, fields in order `Front`, `Back`, `Tactic`, `Source`.
- CSS: system font stack (`-apple-system`, `BlinkMacSystemFont`, `"Segoe UI"`, `Roboto`,
  `"Helvetica Neue"`, `Arial`, `sans-serif`), comfortable line-height, `max-width` for phone width,
  `overflow-wrap: anywhere` on long text, no fixed height, **no `overflow: hidden`**, a restrained
  `.nightMode` contrast pair.
- Card template: front renders `{{Front}}`; back renders `{{FrontSide}}`, an answer rule, `{{Back}}`,
  an optional `{{#Tactic}}` block and `{{Source}}`.
- No external asset: no `@import`, `url(`, `http://`, `https://`, `<link>`, `<script>` or `<img>` in
  CSS or templates. Field text is HTML-escaped by Go; only the template supplies markup.

Field HTML (`internal/note.Fields`): front/tactic/source are escaped text with newlines as `<br>`;
back splits its blank-line paragraphs into `<div class="pq-meaning">` and
`<div class="pq-example">`. Preview, export and push all consume this one function, so they cannot
diverge.

## Export

Default path `<db dir>/passquest-notes.tsv` (`--out` overrides). File content:

```text
#separator:tab
#html:true
#notetype:PassQuest Note
#deck:Pass Quest
#tags:passquest
Front	Back	Tactic	Source
<row>...
```

Written `0600` in a `0700` parent through a temp file in the destination directory, `Sync`, `Close`,
`Rename`; any failure removes the temp file and leaves an existing export untouched. Rows contain
HTML fields, so tabs and newlines inside note text cannot break the format. A re-import of an edited
export can duplicate cards because Anki's text importer has no note id; `push` is the revision path
and the limit is stated in the docs.

## Trade-offs and defaults taken

- **Loopback Node host rather than Go HTTP.** The `local-only` gate forbids `net/http` in first-party
  packages, and notes carry private source text. The host is a narrow allow-listed transport; all
  policy stays in Go and is tested with a fake. Cost: `push` needs Node, while export and every local
  note command do not. (Q-0007-07)
- **Note identity is question + mark, not attempt.** Re-answering a question must not create a second
  card for the same lesson; two marks on one question are legitimately two notes. (Q-0007-09)
- **Unanswered/skipped targets never read the key.** A skipped attempt is treated as unanswered for
  note content even though the attempt row records the key. This is the safe reading of "the answer
  key of an unanswered question never included". (Q-0007-09)
- **Every imported source is restricted.** The repository has no finer rights classification than the
  existing goal-0005 private-source rule, and a false "public" is irreversible. (Q-0007-08)
- **Accept refuses without consent; preview does not.** A card without its example would be a
  misleading note; preview remains send-free and shows exactly what the current decision permits.
  (Q-0007-08)
- **Read-back before update.** `notesInfo` is an extra action beyond the contract's minimum list,
  required by Q-0007-06 and core design: the learner owns Anki edits, so a differing field is a
  conflict unless `--force`. (Q-0007-06)
- **Provider refinement uses a separate ledger and the shared daily budget.** The tutor call table
  requires an attempt id and a coaching mode; reusing it would mislabel notes in tutor history. A
  refinement consumes one provider slot and records its own request identity. (Q-0007-10)
- **Refinement is explicit and optional.** No note command contacts a provider unless `--refine` is
  passed; the deterministic draft is always available and is the evidence path.
- **A changed question refuses a stale-attempt note.** If the current content version differs from the
  version recorded on the attempt, `propose` refuses with `content_changed`; the same check runs at
  preview/accept if the content changes while a draft is open. A note mixing an old answer with new
  text would be misleading. Reverse by using only recorded attempt facts and withholding current text,
  as the tutor does.

## Out of scope, with reasons

- Anki clone, own scheduling, `.apkg`, images or audio, AnkiWeb API calls and mobile apps: contract.
- Real Anki Desktop verification: no binary or endpoint on this host and CI cannot reach the owner's
  desktop; the stub proves protocol behaviour and the real write stays owner evidence (Q-0007-01).
- Automatic phone sync claims: forbidden by the contract; all output says AnkiWeb sync is manual.
- A note browser/editor UI, bulk import, tagging UI and model migration: the CLI is the pre-0011
  surface; goal 0011 owns the workspace.
- Deleting Anki cards or rewriting user edits: destructive and not reversible; conflicts are surfaced.
- Sending note text to any provider except an explicit `--refine` call under recorded consent.
- An exam score, blueprint or pass threshold: still unknown and forbidden.
