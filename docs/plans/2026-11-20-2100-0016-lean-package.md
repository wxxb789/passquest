# 0016 — A lean package that ships only what the app runs: increment plan

Contract: [`../goals/0016-lean-package.md`](../goals/0016-lean-package.md).
Conventions: [`../conventions.md`](../conventions.md). Harness: [`../harness.md`](../harness.md).
Cross-platform rules: [`../cross-platform.md`](../cross-platform.md). Base: `goal/0016-lean-package` at `4633b07`.

## Goal in one sentence

Every package stages the four agent hosts and the pinned Node 22 runtime and nothing else: the one host that
imports npm packages ships as a self-contained ESM bundle built from the locked tree, the three that import none
ship byte-identical, no package carries `node_modules`, the inlined licences' notices travel with the code, and
the installed app proves a study brief on all three OSes — sizes and durable-host cold start measured.

## Defaults taken (record each in OPEN-QUESTIONS as Q-0016-NN; the last entry is Q-0015-06)

1. **Bundling is the shipping rule and staging never falls back.** A host that names a non-`node:` specifier is
   staged as one self-contained ESM bundle built by the pinned Bun; a host that names none is copied
   byte-identically; no package carries `node_modules`, and an unresolvable specifier or a non-JavaScript asset
   fails the run rather than shipping the old tree.
2. **The bundle is built from a generated entry** in a staging temp directory: one namespace import per specifier
   the host names (`Bun.resolveSync` resolves it from `agent/`, so the entry may live outside the tree), then the
   host. A plain `bun build` drops the packages' module initialization. Entry and metafile are staging
   intermediates and never ship.
3. **Names and resolution stay.** The staged file keeps the host's name (`durable-host.mjs`); `agent/package.json`,
   `bun.lock` and `internal/hostpaths` are untouched, and the source tree keeps resolving through
   `agent/node_modules`, so development from `agent/` is unchanged.
4. **No minification, no source maps** in the shipped bundles (reviewable, diffable output).
5. **Notices.** Staging assembles `agent/THIRD-PARTY-NOTICES.txt` from the packages each bundle inlines: their
   `LICENSE`/`NOTICE` texts, their `THIRD_PARTY_NOTICES` files, and where a tarball carries no licence file (all
   `@earendil-works` packages) the SPDX MIT text with the package's own `author` line — disclosed in the evidence
   record.
6. **Cold start** is 15 `status` samples per host on the staged runtime, reported as min/median/max; reported,
   not gated.

### P1 — staging

`harness/lib/package.ts`: delete `stageAgentModules` and the temp install (with `pruneUncopied`, `scanModules`
and `assertPortableModules`, which only served it). Add `bundleHost(root, host, outDir)` and `stageAgent(root,
dir)`: per `agent/*.mjs`, when the source names a non-`node:` specifier (the existing `HOST_IMPORT` regex)
generate the entry (default 2), run `bun build <entry> --target=node --format=esm --outfile
<stage>/agent/<host> --metafile <tmp>/<host>.json` through `process.execPath`, else `copyFileSync`. Use
`--outfile`, never `--outdir` (bun renames `.mjs` to `.js` there). Export `assertLeanAgentTree(dir)`, as
`assertPortableModules` was exported, for fixtures and gates: the tree holds only `*.mjs` plus
`THIRD-PARTY-NOTICES.txt`, no `node_modules`, no symlink, no other file type, and no staged file names a
non-`node:` specifier (an unresolved `import(<bare>)` or a `.node`/wasm asset fails here). Keep `clearStage`, the
icon, `NODE_PINS`, the extract, `node --version`, and add the staged-runtime proof: the staged host answers a
`status` request with `state=status` (a load proof only — a plain bundle passes it; P2 and P3 prove behaviour).

### P2 — the durable matrix over the bundle

`harness/gates/agent-smoke.ts`: lift sections 1–11 into `durableMatrix({ label, host, node })`; run it for the
source host with today's environment, then for the bundle P1's `bundleHost` builds into the gate's temp dir
(`PASSQUEST_AGENT_HOST=<bundle>`, the environment's node). Every existing assertion stays; messages gain the host
label. This is the check that fails when a bundle loses a module init, a tree-shaken export or a dynamic import:
the plain bundle faults at section 1 with `task_faulted`, the generated-entry bundle completes all eleven. Unit
self-test (`self-test.ts`) over the entry generator: one namespace import per named specifier, the host last, so
the prelude cannot be dropped unnoticed.

### P3 — the brief in the installed app

New `harness/gates/package-smoke/brief.ts` (a `desktop-smoke`-style scenario) and case `brief` after `agents`:
seed the data as the coach case does (`import`, attempts, `model use stub/stub-model`), point the stub at a
*delaying* first reply, and run the installed binary's own CLI `agent start --timeout-seconds 1` with no
`PASSQUEST_NODE` and no `PASSQUEST_AGENT_HOST` — the run must be `paused`, which also proves the package's own
runtime and host were found. Then launch the window: Today shows the unfinished brief, `brief-resume` is pressed,
the stub answers step 1, step 2 and the final text, `brief:changed` reports completion, the sheet shows the
completed state, and `agent status`/`report` through the installed binary show two committed steps, an untouched
attempt report, and exactly three provider requests on the one path. The case runs in the `package` group, so all
three OSes prove it, and it fails if the installed host cannot run without `node_modules`.

### P4 — notices

Staging assembles `agent/THIRD-PARTY-NOTICES.txt` from the inlined package set of every bundle it builds (P1's
metafiles, union, deduplicated, sorted): each package's `LICENSE`/`NOTICE` text, each file under its
`THIRD_PARTY_NOTICES`, or, where the tarball carries neither, the SPDX MIT text with the package's `author` line
(default 5). Assembly is a pure exported function (package names, a licence reader, the SPDX fallback) so the
harness self-test can feed it a set with a missing licence and require a failure. The contents check
(`package-smoke/contents.ts`) asserts the installed `agent/THIRD-PARTY-NOTICES.txt` exists and carries every text
the staged bundles required (the staging result carries that set; the package smoke hands it to the scan), and a
fixture case that deletes one text must fail.

## Risks

- **The bundler's init elision changes** (a bun upgrade, a new dependency layout) → the bundle silently half
  initializes; detected by P2's bundle pass (three OSes) and P3's brief case, and recorded as why the entry exists.
- **A tree-shaken or dynamically resolved module disappears** → P1 rejects a staged file naming a non-`node:`
  specifier (including `import(<bare>)`); P2/P3 exercise the modules the brief really uses.
- **Notices lost or wrong** → P4's checks plus the disclosed SPDX fallback for the `@earendil-works` packages.
- **Staging differences on macOS and Linux** (paths, output naming) → the three CI package jobs; the plan avoids
  `--outdir`, which renames the host. **Installer sizes disappoint** (compressed `node_modules` shrink less than
  they look) → P5 reports the staged and installed figures instead of promising an installer number.
- **A future host needs a native asset** → staging fails by rule (default 1), not with a tree that cannot work.

## Evidence plan

Local (Windows): the package smoke once at the end of each touched step, agent-smoke and the new self-test cases,
`docs-links` when docs change, `gofmt`/`vet`/`build`/`test` to show no Go side moved. CI: the `core` jobs (the
bundle pass on three OSes) and the `package` jobs (the brief case, the sizes). Disclosed limits: the before
numbers come from main's tree and the v0.15.0 assets; macOS and Linux are proven only by CI; the SPDX-fallback
notices are our wording, not upstream text; cold start is reported, not gated.
