# 0015 — Know when a newer Pass Quest exists: increment plan

Contract: [`../goals/0015-know-when-a-newer-version-exists.md`](../goals/0015-know-when-a-newer-version-exists.md).
Conventions: [`../conventions.md`](../conventions.md). Harness: [`../harness.md`](../harness.md).
Cross-platform rules: [`../cross-platform.md`](../cross-platform.md). Base: `main` at `613d799`.

## Goal in one sentence

From Settings, and only when the learner asks, the desktop app makes one anonymous request to this repository's GitHub
Releases. It shows whether a newer published release exists, and if so links to its page in the system browser. It downloads
nothing, installs nothing and writes nothing, and the local-only gate allows exactly that one request from exactly one package.

## Facts this plan rests on (scouted 2026-11-19)

- **Network rule.** `harness/gates/local-only.ts` forbids `net`, `net/http`, `net/rpc` and `net/smtp` in every first-party
  package (rule 1). It also forbids `net/http`, `net/rpc` and `net/smtp` among the transitive deps of `./cmd/passquest`
  (rule 2). `cmd/passquest-desktop` links MyGo, which links `net/http`, so only rule 1 applies to it.
- **Service surface.** The window reaches Go only through the MyGo-bound `Study` service (`internal/desktop/study.go`). Its
  TypeScript client `desktop/web/src/api/mygo.ts` is generated with `MYGO_GENERATE`, and desktop smoke checks that it is fresh.
  `internal/desktop` must not import `internal/cli` (module boundaries in the same gate).
- **External links.** MyGo 0.10.0: without `SetWindowOpenHandler`, `window.open()` and `target="_blank"` http(s) URLs open
  in the default browser, and everything else is denied (`window.go` `SetWindowOpenHandler`, architecture.md). The app
  sets no handler today.
- **Smoke-only environment.** The smoke hook reads `PASSQUEST_DESKTOP_SCRIPT` and `PASSQUEST_DESKTOP_RESULT`.
  `PASSQUEST_DESKTOP_CONTENT_SIZE` already sets a precedent: a variable read only when `EnvScript` is set (Q-0012-05).
- **Child processes.** Desktop smoke fails a launch that leaves a child process or a listening TCP socket in the app tree.
  A stub server in the harness process is outside that tree.
- **Version.** `mygo.json` `version` is `0.13.0`, and MyGo writes it into the package names. No Go constant carries it.
  The repository is public and has **no** GitHub Release yet.
- **Settings.** The settings screen is `desktop/web/src/views/settings.ts`, with controller
  `desktop/web/src/controllers/settings.ts`. Its rows open one at a time (`ui.settings.open`). Text is bilingual through `T(zh,
  en)` (`core/i18n.ts`). desktop-ux audits named states at several sizes (`harness/gates/desktop-ux.ts`,
  `harness/lib/ux-page.ts`).

## Defaults taken (record each in OPEN-QUESTIONS as Q-0015-NN)

1. **On demand only.** The check never runs on its own: there is no check at start-up, no timer and no stored preference. A
   Settings row "Updates" holds the one-line disclosure and a "Check for updates" button. Because nothing is scheduled, no
   frequency setting exists. The settings state before the first check is "not checked in this session".
2. **The request.** `GET https://api.github.com/repos/wxxb789/passquest/releases/latest`, with:
   - headers `Accept: application/vnd.github+json` and `User-Agent: PassQuest` (no version, no device or learner field);
   - no cookies, no query, no body, no auth;
   - redirects refused;
   - a 10 s total timeout and a 1 MiB response cap.
   `/releases/latest` already excludes drafts and pre-releases. The app also ignores an entry marked `draft` or
   `prerelease`, or one whose tag is not a valid semver above the running version.
3. **States** (`update.Status`):
   - `newer`: version, published date, release-notes link and download page;
   - `current`: the running version is the latest, or no release exists (HTTP 404 reads as "no release published yet",
     a distinct line within `current`);
   - `unavailable`, "could not check": offline, timeout, HTTP 403/429 (rate limit), 5xx, a malformed body or an invalid tag.
   The failure detail is a short reason shown in small text; study is never blocked.
4. **Links.** The app does not show a link taken from the response verbatim. A release-notes or download URL is shown only
   if it is `https://github.com/wxxb789/passquest/releases/...`. Otherwise the app builds
   `https://github.com/wxxb789/passquest/releases/tag/<tag>`. The link is an `<a target="_blank" rel="noopener">`, so MyGo
   hands it to the system browser. Nothing is downloaded.
5. **Version.** `mygo.json` moves to `0.15.0`. A Go constant (`update.Version`) holds the same value, and a Go test fails
   if the two differ.
6. **Smoke-only endpoint.** `PASSQUEST_DESKTOP_UPDATE_URL` is read only when `EnvScript` is set, and only an
   `http://127.0.0.1:<port>/...` value is accepted; anything else is ignored. `PASSQUEST_DESKTOP_UPDATE_TIMEOUT_MS` follows
   the same rule and lets the timeout state run fast. A packaged run without the smoke hook can only reach the constant
   endpoint.

### P1 module

`internal/update` exposes:

- `Version` (const);
- `Endpoint` (const, the URL in default 2);
- `type Result` (state, latest version, published date, notes URL, download URL, reason);
- `Check(ctx context.Context, client *http.Client, endpoint, current string) Result`;
- a semver comparison.

The package imports nothing first-party.

Go tests, all against `httptest` loopback servers:

1. One test per state in default 3: newer, current (equal), older tag, pre-release flag, draft flag, 404, 403 with
   `x-ratelimit-remaining: 0`, 429, 500, malformed JSON, a body over the cap, an invalid tag, a timeout, and a refused
   connection.
2. **Captured request.** The server records the method, path, raw query, every header, the body and the cookies. The test
   fails if anything differs from the allowed set: `GET`, the exact path, no query, empty body, only the headers `Accept`,
   `User-Agent` and `Accept-Encoding` (Go's default), and no cookie.
3. Link validation: a foreign `html_url` falls back to the built tag URL, and `javascript:` and `http:` links are refused.
4. The version constant equals `mygo.json`.
5. The smoke-only override accepts only a `127.0.0.1` http URL, and only with the smoke hook set.

### P3 rules (local-only gate)

1. `internal/update` is the only first-party package that may import `net/http`. Every other package keeps rule 1.
2. `./cmd/passquest` deps must not include `internal/update` (beside rule 2, so the CLI cannot link it).
3. The only importers of `internal/update` are `internal/desktop` and `cmd/passquest-desktop`.
4. The non-test Go files of `internal/update` contain exactly one http(s) string literal, and it is the constant endpoint.
   The host must be `api.github.com` and the path `/repos/wxxb789/passquest/releases/latest`. The literals are read with the
   existing `go/parser`-based tool (`harness/tools/pathtypo` or a sibling), not a regex. Link-prefix literals for
   `https://github.com/wxxb789/passquest/releases/` are allowed as the second permitted form, and are checked the same way.
5. Self-test cases, each failing with its own message:
   - another first-party package imports `net/http`;
   - the CLI links a network client (or `internal/update`);
   - the endpoint literal names another host.
   Existing cases that already cover the first two remain; add only what is missing, and say which.

The gate title and pass line name the exception (for example "1 allowed network package: internal/update →
api.github.com").

### P4 scenario

A loopback stub in the harness process serves a scripted sequence and records every request. One launch sets
`PASSQUEST_DESKTOP_UPDATE_URL` and `PASSQUEST_DESKTOP_UPDATE_TIMEOUT_MS`. The page script presses "Check for updates" once
per stub step and reads the rendered state:

1. newer;
2. current (equal tag);
3. an older tag, then a pre-release entry (both read as current);
4. 404 (no release yet);
5. malformed body;
6. 429 rate limit;
7. a stalled response past the timeout;
8. the stub closed (offline).

Assertions:

- each state's text and the link `href` (must be the repository release URL) and `target`;
- every captured request has only the allowed method, path, headers and no body;
- no request reached any other path;
- the data directory's file listing (names, sizes, mtimes) is identical before and after the checks;
- Today still renders afterwards (study unaffected).

The scenario never clicks a link, so no browser opens on a runner.

## Risks

- **WebView link handling.** A `target="_blank"` link might not reach the browser in one WebView. The scenario asserts only
  the `href` and `target`, and the evidence states that the browser hand-off is MyGo's documented default, not observed on
  CI.
- **Go's transport.** It may add headers (`Accept-Encoding: gzip`). The allowed set names them explicitly; a new Go version
  that adds one fails the capture test loudly rather than silently.
- **Proxy settings.** A proxy from the environment would send the request elsewhere. `Proxy: nil` on the client keeps the
  request direct, so the evidence matches the code. This is a disclosed limit for learners behind a mandatory proxy.
