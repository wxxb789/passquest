# 0011 — Desktop study workspace

Contract: [`../goals/0011-desktop-study-workspace.md`](../goals/0011-desktop-study-workspace.md)
Prerequisites: 0005, 0007, 0009 (all done). Owner decisions: Q-0011-00. Defaults: Q-0011-01 … Q-0011-09.
Design reference: [`../../design/prototypes/c-stage.html`](../../design/prototypes/c-stage.html) and
[`../../design/prototypes/BRIEF.md`](../../design/prototypes/BRIEF.md).

## Outcome

A MyGo desktop window over the same Go core the CLI uses: Today, practice + feedback + coach, assessment +
report, Anki, settings — real data, real evidence, keyboard-first, interruptible, with no TCP listener and no
credential outside the OS credential store.

## Why a new dependency

`github.com/egoist/mygo` (pinned `v0.9.0`, pure Go via purego, no cgo) is the shell the core design names.
The standard library has no webview. It links `net/http` transitively, which is why the desktop is a separate
binary and `cmd/passquest` keeps its "no HTTP client linked" rule. Its `Secrets` module is the OS credential
store core design §7 requires; no second module is added for that.

## Layout

```text
cmd/passquest-desktop/        main: CLI args → cli.Run (same exit codes); no args → desktop.Run
internal/studio/              exported DTO types shared by the Go service and the bound API (pure data)
internal/cli/workspace*.go    exported Workspace facade reusing the CLI's unexported orchestration
internal/store/               additions only: learner settings, open presentation lookup, run list (schema 17)
internal/desktop/             MyGo app: bound service, data path, secret-backed getenv, lifecycle, smoke hook
internal/desktop/web/         go:embed root: committed index.html + generated dist/ (gitignored)
desktop/web/                  TypeScript + CSS source (tsconfig of its own), bundled by Bun
desktop/web/src/api/mygo.ts   client generated by MyGo from the bound Go service (committed, checked fresh)
harness/lib/desktop.ts        bundle + build helpers shared by the gate and `bun run desktop:build`
harness/gates/desktop-smoke.ts
```

`internal/cli` and `internal/desktop` must not import `net`, `net/http`, `net/rpc` or `net/smtp` directly; the
local-only gate's first-party import rule is extended to `./cmd/passquest-desktop` and still covers
`./internal/...`. Rule 2 (`go list -deps ./cmd/passquest` has no HTTP client) is unchanged.

## Public shape — the Workspace service

One long-lived `*cli.Workspace` per window, opened on the desktop's database path with the same `Options`
seams the CLI uses (`Getenv`, `Now`, transports). Writes are serialised inside the workspace; each call opens
the store per operation exactly like a CLI command (the durable host writes through a second process). Every
method returns `studio` types or a typed error `studio.Error{Code, Message, Action}` whose codes reuse the CLI
error codes (`invalid_input`, `assessment_active`, `pool_floor`, `no_credential`, …).

| Area | Methods (Go, exported on `Workspace`) | Notes |
|---|---|---|
| Today | `Today() (studio.Today, error)`; `SetLearnerSettings(studio.LearnerSettings) error` | recommendation as structured target (`kind`, `skill`, `content_id`, `question_id`, `source_id`) plus the CLI command string; skill evidence + inference; pool; last run; Anki counts by state; latest unfinished brief with step x/N; find status; active model + per-provider budget; prep day from first attempt; exam date / daily minutes optional |
| Practice | `StartPractice(studio.PracticeRequest) (studio.PracticeItem, error)`; `ResumePractice() (*studio.PracticeItem, error)`; `OpenHint(token) (studio.PracticeItem, error)`; `Answer(token, label) (studio.Feedback, error)`; `Skip(token) (studio.Feedback, error)` | request kinds: `next`, `skill`, `tactic` (`guided`/`independent`), `sample`, `source`; item carries passage (title, source label, paragraphs), question without key, `condition` (`independent`/`assisted`/`re_exposure`/`revisit`) and `can_count`, `hint_available`, `presented_at`; a presentation token binds answer to the displayed item; elapsed = answer time − presented_at |
| Feedback | (returned by Answer/Skip) | grade, verified key label/text, all option explanations with `missing` flags, evidence sentence with offsets in the passage, tactic link, attempt id and condition |
| Coach | `CoachPreview(attemptID, mode) (studio.CoachPreview, error)`; `CoachAsk(attemptID, mode) (studio.CoachReply, error)`; `GrantConsent(source, provider)`, `RevokeConsent(source, provider)` | preview = provider/model/verified, external flag, payload summary + exact request sha/bytes, consent state, budget slot; ask reuses `runTutorAsk` semantics incl. failover; failure → typed failure with action |
| Assessment | `AssessmentPool()`, `StartAssessment(size, minutes)`, `AssessmentState()`, `PresentAssessmentItem(run)`, `AnswerAssessmentItem(run, position, label)`, `ResumeAssessment(run)`, `AbandonAssessment(run)` | step API extracted from `runAssessmentLoop`; navigator states without correctness; deadlines in absolute time so the window clock is display-only |
| Report | `AssessmentReport(run)`, `AssessmentCompare(a, b)`, `AssessmentRuns()` | reuse `assess.BuildReport` / `assess.Compare` |
| Anki | `ProposeNote(studio.NoteRequest)`, `PreviewNote(draft, fields)`, `AcceptNote(draft, fields)`, `SkipNote(draft)`, `Notes()`, `PushNotes(force bool)` | preview returns the real `note.RenderCard` HTML + `note.ModelCSS`; marks come from passage selections (≤120 runes, existing `NormalizeMark`) |
| Settings | `Models()`, `UseModel(id, endpoint)`, `TestModel(id, endpoint)`, `Budget()`, `Consents()`, `SetCredential(provider, key)`, `ClearCredential(provider)`, `Services()` | credentials go through an injected `CredentialStore` (desktop: `mygo.Secrets`; tests: in-memory) and are only ever reported as present/missing |
| Brief | `BriefStatus()`, `ResumeBrief()`, `CancelBrief()` | resume runs asynchronously in the desktop layer and emits an event when the host returns |

The desktop binds one service struct (`desktop.Study`) that forwards to the workspace; MyGo generates the
TypeScript client and types from it.

## Store additions (schema 17, additive, migration-tested)

Schema 16 was taken by goal 0014 (deck read-back); this goal adds migration 17.

- `learner_settings(key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT NOT NULL)` for `exam_date` and
  `daily_minutes` only.
- `practice_presentations(token TEXT PRIMARY KEY, kind, content_id, question_id, source_id, tactic_id,
  skill_id, stage, content_version, presented_at, hint_opened_at, closed_at, closed_reason, attempt_id)` — the
  open item for resume (`closed_at` is empty while open, as in the assessment tables); it is closed in the same
  transaction that appends the attempt, which makes a repeated answer return the stored feedback. Attempts stay
  append-only and unchanged.
- read queries: latest open presentation; list assessment runs.

## Frontend

`desktop/web/src`: `main.ts`, `core/` (state, i18n zh/en, html escaping tag, router, render + layers + focus,
keyboard, clock, toast via textContent), `chrome/` (top bar, dock, orb), `components/` (satellite, constellation
icon, passage with evidence + marks, options, condition capsule, call strip, sheet, dialog), `views/` (today,
practice, feedback, coach, assess, report, anki, settings), `api/` (generated `mygo.ts` + a thin typed wrapper).
CSS is the prototype's, split by section into `desktop/web/styles/*.css`, with its tokens unchanged.
Model replies and any learner/imported text are inserted as text, never as HTML. The Anki preview renders the
real card HTML inside a sandboxed `iframe srcdoc` with the real model CSS.

## Edge-case semantics

- Assessment active: practice, coach, skill and model actions return `assessment_active` and the window
  routes to the run.
- A token whose item was already answered returns the stored feedback (idempotent re-submit).
- Node missing: practice works; coach, push and brief show `node_unavailable` with the action.
- AnkiConnect unreachable: accepted notes stay queued and are shown as such.
- No reviewed imported source: assessment shows the pool shortfall from `pool_floor`.

## Evidence plan

- Go tests for every `Workspace` method against temp databases (DTO shape, elapsed time, assisted after hint,
  idempotent answer, resume, assessment step API, credential store never touching SQLite).
- `desktop-smoke` gate: bundle + build `cmd/passquest-desktop`, regenerate the MyGo client and compare with the
  committed one, then run scenarios with a hidden window and a fresh `WEBVIEW2_USER_DATA_FOLDER`, a temp data
  dir and loopback provider/AnkiConnect stubs; each scenario is a script evaluated in the page that drives the
  DOM and returns JSON; the gate cross-checks the database with the CLI. Hard watchdog per launch; Linux runs
  under `xvfb-run` with WebKitGTK installed by the workflow.
- Typecheck gate covers `desktop/web/tsconfig.json` as a second project.
- Self-test: a desktop binary whose window stays blank and a frontend project with a type error must fail.
